# Security Policy

## Supported Versions

Security support is provided for actively maintained releases of Saudade. Older releases and development snapshots may receive fixes on a best-effort basis.

| Version | Supported |
| --- | --- |
| Latest release | Yes |
| Older releases | Best effort |
| Development snapshots | Best effort |

## Reporting a Vulnerability

Please do not publicly disclose an unpatched security vulnerability in an issue.

Report security concerns privately to:

jadhavdurvesh65@gmail.com

Include, when possible:

- Description of the vulnerability.
- Affected version or commit.
- Steps to reproduce.
- Relevant logs or proof of concept.
- Potential impact.
- Suggested mitigation.

## What Should Be Reported Privately?

Examples include:

- Credential or secret exposure.
- Malicious code execution introduced into the repository.
- Vulnerabilities affecting project tooling.
- Problems that could compromise users of project infrastructure.

Ordinary bugs, model-quality problems, performance issues, and feature requests should normally use GitHub Issues.

## Disclosure

Please allow maintainers reasonable time to investigate and address a reported vulnerability before public disclosure.

Saudade is an experimental research project and is not presented as a security-critical system.
